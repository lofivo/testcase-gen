# 特殊性质 → 生成代码 翻译规范

题面的「特殊性质」（如 A/B/C…）是对某组测点输入的额外约束。生成器必须让该组测点的输入**严格满足**该性质，同时保持**随机性与代表性**，避免退化成千篇一律的最简数据。

## 通用原则

1. **先构造、后扰动**：先按性质生成"骨架"（满足性质的极端/结构），再叠加随机扰动，使其既有代表性又不像手搓的样例。
   - 例：性质「`a_i` 递增」→ 先 `a_i = i`，再整体加随机偏移或局部打乱，而不是直接 `a_i = i` 一成不变。
2. **性质是下界，随机是上界**：在满足性质的前提下尽量扩大随机空间。满足 `L_j = R_j` 时，`R_j` 仍应在 `[1, n]` 内随机。
3. **边界仍要覆盖**：性质组内也要覆盖该性质下的极端（如性质「`R_j ≤ 32`」里，`R_j` 要取到 1、32、以及若干中间值）。
4. **每组至少一个测点**：题面测试点表里每个「性质」至少落在对应编号的测点上，且大数据测点也要带性质（表里往往如此，如 `6,7` 是满 `n` 但带性质 A）。

## 常见性质类别与翻译范式

以下用 `rnd` 表示 testlib 的 `rnd` 实例。`n` 为该测点的上限。

### 区间/下标类

| 性质（自然语言） | 生成范式 |
| --- | --- |
| `L_j = R_j`（单点查询） | `L = R = rnd.next(1, n)` |
| `R_j ≤ k` | `R = rnd.next(1, min(n, k)); L = rnd.next(1, R)` |
| `L_j ≤ k` | `L = rnd.next(1, min(n, k)); R = rnd.next(L, n)` |
| `L_j > n/2` | `L = rnd.next(n/2+1, n); R = rnd.next(L, n)` |
| `L_j ≤ a 且 R_j ≥ b` | `L = rnd.next(1, a); R = rnd.next(max(L, b), n)` |
| 区间互不重叠 | 先生成若干不交区间（分段或排序后取间隔），再打乱顺序 |

### 值域类（数组/序列）

| 性质 | 生成范式 |
| --- | --- |
| `a_i` 全为正 / 全为负 / 全为 0 | 限定 `rnd.next` 的下界/上界，或固定值 |
| `a_i` 递增 / 递减 | 生成后 `sort`，或 `a_i = i * step + rnd.next(0, gap)` |
| 所有 `a_i` 相等 | `x = rnd.next(lo, hi)` 后全部赋 `x` |
| `a_i` 两两不同（排列） | `rnd.perm(n)` 再映射到值域 |
| 只有 0 和 1 | `rnd.next(0, 1)` |
| 出现大量重复/众数 | 先随机取少数几个值，再从中 `rnd.next` 采样填充 |

### 图/树类

| 性质 | 生成范式 |
| --- | --- |
| 树是一条链 | 连 `(i, i+1)`，再 `rnd.shuffle` 节点编号 |
| 树是菊花（star） | 中心连其余所有点 |
| 树是二叉树 | 逐点随机挂到已生成点的左/右儿子 |
| 树随机 | 随机 `prufer` 序列，或逐点随机连一个已有点 |
| 无重边/自环 | 用 `set<pair<int,int>>` 去重，或保证 `u < v` |
| 图为 DAG | 边方向固定为编号小的指向大的 |
| 图为完全图 | 枚举所有点对 |

### 字符串类

| 性质 | 生成范式 |
| --- | --- |
| 只含 `a` | `rnd.next("a{" + to_string(n) + "}")` |
| 只含两种字符 | 先随机取两个字符，再从中 `rnd.next` 采样 |
| 回文 | 生成前半段，后半段镜像 |
| 随机小写 | `rnd.next("[a-z]{1,100}")` |

### 排列/组合类

| 性质 | 生成范式 |
| --- | --- |
| 递增排列 | 恒等排列 `1..n` |
| 递减排列 | `n..1` |
| 随机排列 | `rnd.perm(n)` |
| 含大量逆序对（卡 `n²` 排序） | 递减排列 |

## 无法机械翻译时

若某性质过于复杂（如「答案总为 0」「满足某 DP 状态」），先在生成器里实现一个**判定函数** `bool sat(...)`，再走「生成 → 若不满足则重生成」的 rejection 循环，或直接从满足性质的最小结构出发变换。必要时在小数据上写一个 `check` 辅助验证，确保性质成立。

## 校验

- 生成器负责**保证**性质成立（构造即满足）。
- 校验器（validator）只兜底**全局数据范围**；如需按测点校验性质，可在 validator 内按测点加 `ensuref`（见 `templates/validator.cpp` 注释）。
- 生成后务必**人工抽查**每个性质组的 `.in`，确认性质真的成立（这是最容易出错的一步）。
