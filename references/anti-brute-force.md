# 大测点 / 卡暴力策略

目的：让朴素暴力（`O(n²)` 及以上）在大数据上 TLE，让常数优化过的暴力也无法侥幸通过。

## 1. 规模定档

- 大数据取题面**允许的最大 `n`（及 `q`）**，不要"够大就行"。
- 依据**标程复杂度**定档：标程 `O(n log n)` 时，最大 `n` 应使 `O(n²)` 约 `≥ 10^9` 次基本操作，必超 1–2s。
  - `n = 5×10⁴` → `n² = 2.5×10⁹`，足够卡掉 `O(n²)`。
  - `n = 10⁵` → `n² = 10¹⁰`，卡掉 `O(n²)`；若暴力是 `O(n³)`，`n = 3000` 即 `2.7×10¹⁰` 已够。
- 若题面有多个变量，**同时拉到最大**（`n`、`q` 都取上限），别只拉一个。

## 2. 最坏输入，而非纯随机

随机数据常让暴力"平均"很快、靠小常数侥幸通过。**对抗性构造**才是关键：

- 让复杂度项**每次都满负荷**：如区间查询题，出大量**长区间**（`L=1, R=n`）而非随机短区间；让 `O(n²)` 的每次 `O(n)` 都真正跑满。
- **逆序/全等/极端值**：排序、最值、计数类题，逆序或全等常触发最坏路径。
- **卡 `std::` 的坏 case**：如对基于哈希的做法出哈希冲突数据（若在数据范围允许内），对快速排序出近乎有序的数据。
- 对 `O(n√n)` / 分块类，出使块内/块间都最坏的分布。

## 3. 覆盖每个性质组的大数据

- 表里带性质的组（如例中的 `6,7` 性质 A、`13` 性质 D）本身就是**满 `n` 的大数据**，务必按其性质生成，别在满 `n` 时丢掉性质。
- 每个「性质 + 满 `n`」组合至少一个测点，保证卡暴力覆盖到所有性质分支。

## 4. 验证

- 把暴力丢进 `wrong/`（如 `wrong/bf.cpp`），错解自检会跑它；满 `n` 点上它应 TLE，从而被"击败"。
- 若暴力在满 `n` 点侥幸 AC（说明常数太小或 `n²` 不够大），提高规模或加强对抗性构造。
- 关注 **TLE 与 WA 的分工**：暴力被 TLE 击败（数据够大），假算法被 WA 击败（数据戳中它的错）——两者都要有，缺一不可。
