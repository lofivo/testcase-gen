# 坑点与易错点清单（驱动测点设计）

无论题面是否有测试点表，测点都应在边界与易错点上覆盖。**有表时**：表内的每个性质/上限组各放若干点，并在「无性质」组里塞边界。**无表时**：按下述清单逐类设点，通常约 10–20 个。

## 1. 边界值（务必覆盖）

- 最小/最大：`n = 1`、`n = max`；每个变量取到题面声明的上、下界。
- 区间端点：`L = R`（单点）、`L = 1`、`R = n`、`L = R = 1`、`L = R = n`。
- 空集/全集：查询范围为空（若合法）、覆盖整个序列。
- 恰好卡边界：`n = 1e5` 时 `a_i = ±1e5`，检验边界是否算对。

## 2. 数值与溢出

- **溢出**：`n`、`q` 或权值乘积可能超过 `int32`（如 `n·q ≈ 5×10⁴·10³ ≈ 5×10⁷` 尚可；但 `n²`、`a_i` 之和、答案取模等极易溢出）。**答案需 `long long` 时务必出到会溢出的数据**，检验标程与错解都用了 64 位。
- 负值、零、正数混排；`a_i = 0` 常被漏判。
- 取模题：答案恰好为模数倍数、结果为 0、负余数。

## 3. 结构退化

- 全部相等、严格递增、严格递减、逆序。
- 大量重复元素（众数/计数类题目容易写挂）。
- 排序后相等元素相邻。

## 4. 常见算法易错点

- **off-by-one**：下标从 0/1 开始、循环边界、区间左右开闭。
- **初始值**：`ans = 0` 还是 `-inf`；`dp` 初始化为 0 还是 `-inf`。
- **哨兵/空状态**：空序列、单个元素、前缀和越界。
- **只处理正数或只处理负数**：符号统一时，对偶情况漏了。
- **贪心冒充 DP**：看似可贪心实则需 DP 的题，构造贪心会错的数据。
- **局部最优 ≠ 全局最优**：构造多阶段决策题，让贪心在早期"贪便宜"而后翻车。

## 5. 特判与格式

- 输出末尾是否多余空格/空行（checker 逐 token 比较会宽容，但标程/错解若格式不一致会误判）。
- 多测（`T` 组）时 `T=1` 与 `T=max` 都要出。
- 无解/特判分支（如「无解输出 -1」）要出到该分支的数据。

## 用法

设点时不求每点都命中一个坑，而是：**小数据点覆盖边界与易错分支**（让错解暴露为 WA），**大数据点覆盖最坏复杂度**（让暴力暴露为 TLE）。两者合起来即完整覆盖。每设一个点，在题目根目录的 `README.md` 里写清它针对哪个坑。
